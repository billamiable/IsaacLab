Skill Proposal

Isaac Lab Teleop Enablement Skill 设计提案

这个 skill 的目标不是“一键适配任意机器人”，而是把一个新的 embodiment / env / task 接入 Isaac Lab teleop 的工程流程做成可复用、可验证、可教学的工作流。Skill 应该提供一个可跑 example，用户和 agent 可以先跑通 example，再把同样的原子步骤迁移到新机器人或新任务上。

整理日期：2026-06-05。示例来自 G1 Dex1 + Pico motion controllers + Isaac Lab headless visuomotor recording enable 过程。

1. Skill 的定位

适配 teleop 不是纯代码生成任务。它同时涉及机器人资产、关节命名、运动学模型、输入设备、场景、相机、录制、headless 渲染和人工验收。一个好的 skill 应该把这件事拆成稳定的 atomic skills，并要求每个 atomic skill 都产出可检查证据：JSON、截图、MP4、HDF5、diff 或文档。

输入

机器人 USD/URDF、参考 Isaac Lab task、目标 teleop 设备、目标动作语义、是否需要 visuomotor 观测。

输出

可注册 task、retargeter/action 配置、相机配置、record 命令、smoke test、视频证据和适配报告。

边界

Skill 不承诺自动完成所有物理调参；它承诺用固定顺序暴露问题并提供下一步工程判断。

2. 建议的 Example 形式

Skill 包里应该带一个小而真实的 example，而不是只给抽象说明。G1 Dex1 这个例子很适合，因为它覆盖了资产、gripper、双手 motion controllers、headless、三相机和 HDF5/MP4 数据闭环。

Example 阶段命令 / 产物用户学到什么
资产 smoke加载 G1 Dex1 USD，移动 gripper 或 wrist，保存截图/短视频。确认资产、joint name、articulation 和 headless 渲染是可用的。
Mock teleop模拟 Pico controller raw packet，经过 retargeter 驱动 wrist + gripper。区分 raw input、retargeted action、joint target、真实设备输入。
Task scenetable + blocks + warehouse，固定下半身，验证 reachability。如何把机器人放进真实任务场景，而不是只看单独机器人。
Camera / visuomotorego + left wrist + right wrist RGB，录 HDF5，再转 MP4 / composite。如何配置相机挂载、FOV、观测 key 和数据闭环。
Real Pico recordingrecord_demos.py --teleop_device motion_controllers --enable_cameras --headless真实设备联调时如何验证控制链、success、reset 和数据导出。
Example 的价值在于可复制：用户不需要先理解全部细节，只要能跑出一个 MP4 和一个 HDF5，就能反向学习每个配置为什么存在。

3. 总体流程拆解

Phase A
Asset Probe

确认机器人资产能被 Isaac Lab / Isaac Sim 正确加载，基础 articulation、joint、link、mesh 没有硬错误。

  • 列出 articulation root、joint name、body/link name、gripper joint limit。
  • 用 headless 脚本加载 USD，保存全身截图或短视频。
  • 分别移动 gripper 和一小段 upper-body trajectory，确认没有 NaN、爆炸、反向或丢 mesh。
Phase B
Action Slice

先打通最小控制切片，而不是一开始就做完整任务。

  • 先控制 gripper，再控制 wrist / arm，再组合 upper body + gripper。
  • 把 action space 拆成可解释维度，例如左右 wrist SE3 + 左右 gripper scalar。
  • 用 mock action 或 scripted trajectory 保存视频，作为后续比较基线。
Phase C
Teleop Retarget

把真实或模拟输入设备接到 action slice。

  • 定义 controller raw data schema，包括 pose、trigger、handedness、button state。
  • 明确绝对控制还是相对控制，校准 controller pose 与 robot wrist / gripper center 的对齐关系。
  • 构建 retargeter：raw controller -> target wrist pose + gripper open/close。
Phase D
Scene / Task

把机器人放进可操作任务，而不是只在空场景里摆动。

  • 加入 table/object/warehouse 等场景资产，解决机器人与桌子的高度和碰撞关系。
  • 调整 object 初始布局，让任务动作路径符合机器人 reachability。
  • 定义 success criterion：任务几何 + release/open 状态 + 连续稳定步数。
Phase E
Camera / Data

把任务升级成 visuomotor 数据采集任务。

  • 挂载 ego / wrist cameras，明确 prim path、link parent、offset、orientation。
  • 调 FOV：wrist 相机通常不宜过广，ego/chest 相机可以更广以覆盖任务上下文。
  • 把 RGB key 放入 policy observation，录 HDF5，转 MP4/composite 供人工检查。
Phase F
Real Device

用真实设备完成一次数据闭环。

  • 用 headless + CloudXR / OpenXR 启动真实 teleop。
  • 验证控制方向、gripper mapping、start/stop/reset、success export。
  • 把 HDF5 转成视频，检查图像质量、动作质量和成功片段是否符合训练预期。

5. Camera 配置作为独立能力

Camera 不是附属项，而是 visuomotor skill 的核心 atomic skill。它至少包含挂载方式、视角语义、FOV、数据 key、headless 渲染稳定性和人工检查视频。

相机挂载

  • 优先挂在真实存在的 USD prim / Xform 上。
  • 如果 source USD 不方便直接改，可用 overlay USDA 增加 camera prim。
  • CameraCfg 可用 spawn=None 绑定已有 camera prim。

FOV 调整

  • focalLength 越小，FOV 越大。
  • horizontalAperture 越大，FOV 越大。
  • wrist camera 适合看夹爪附近，不宜过广；ego/chest camera 适合更广，覆盖桌面和任务上下文。
示例：当前 G1 Dex1 camera 调整
left_wrist_cam / right_wrist_cam:
  focalLength = 18
  horizontalAperture = 20.955

ego_cam:
  focalLength = 12
  horizontalAperture = 20.955

结果：wrist 视角保持局部抓取细节，ego 视角扩大到更适合观察桌面任务。
已经录出的 HDF5 不能通过改 FOV 后处理变广；FOV 改动必须在重新录制前生效。每次 camera 调整后都应重新录一小段 HDF5 并导出 composite MP4。

6. Headless 验证是共享 Skill

机器人适配里最容易浪费时间的地方，是“代码能跑但视觉上不对”。因此所有阶段都应该能产生 headless 可检查证据，而不是等到真实 Pico 测试时才发现问题。

验证类型检查点失败时常见原因
Screenshot机器人全身、桌子、object 是否在画面内。viewer/camera 距离错误，场景 offset 错误，asset scale 错误。
Scripted MP4gripper 是否真的夹爪运动，wrist 是否跟随目标。控制的是 wrist 而非 gripper center，左右 mapping 反，joint limit 错。
Camera MP4ego/wrist 视角是否能看到任务区域。camera 朝向、offset、FOV、background 或 clipping 配置问题。
HDF5 Auditdemo 数、success attr、obs key、image shape 是否正确。success 太严，camera 未进 policy obs，record_demos 未 export。

7. 从本轮 G1 Dex1 得到的可复用经验

  • 不要一开始就追求完整抓取任务，先证明 gripper、upper-body、mock input、scene、camera 各自可控。
  • USD 与 URDF 通常各有用途：USD 服务仿真和渲染，URDF/kinematic model 服务 IK 和 frame 语义。
  • camera 可以用 overlay USDA 方式挂到机器人 link 上，避免直接破坏原始资产。
  • headless + XR + camera 可能需要保持 active viewport，且只采需要的数据类型，例如 RGB，不一定要 depth。
  • success criterion 要贴合遥操作数据录制：任务几何、gripper release、稳定步数都要考虑。
  • 每次调 object layout 或 camera FOV，都要重新录 HDF5 并转 MP4；不要只看代码 diff。

9. 最小操作手册

  1. 先跑 example，确认本地 Isaac Lab / Docker / headless rendering / HDF5 export 都正常。
  2. 新机器人先做 asset probe，不直接改完整 task。
  3. 先做 gripper 或单 arm action slice，再接 teleop retargeter。
  4. 每一阶段都存视频，用户用眼睛验收，而不是只看日志。
  5. 最后才加入真实场景、camera、success、record_demos 和真实设备。
判断一个 adaptation 是否已经进入可用状态，不是看“代码是否能启动”，而是看是否能稳定地产生：可控动作、成功 reset/export、可用 HDF5、可检查 MP4。
