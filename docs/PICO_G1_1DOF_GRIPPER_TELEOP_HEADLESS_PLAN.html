Isaac Lab Teleop Design Note

Pico Motion Controller 控制自定义 G1 1DOF Gripper 的方案

本文总结现有 Isaac-Stack-Cube-Franka-IK-Abs-v0 motion controllers 链路如何迁移到 自主拼装的 Unitree G1 USD，并说明如何在 headless 模式下做开发、自动测试和视频验证闭环。

目标 USD: RobotLearningLab_Dataset/usecase/humanoid_teleop/g1_29dof_dex1_1_v4_test_good.usd

结论

可行。 现有 Franka 示例已经证明 Pico motion controller 可以作为输入源：右手柄位姿控制末端，trigger 控制 1DOF gripper。 因此 Pico、CloudXR、OpenXR、Isaac Lab device factory 这一层基本不用重做。

主要工作在 G1 侧：把原来面向 TriHand/Inspire 灵巧手的多关节手部动作，替换成自定义 G1 USD 上的 1DOF 并联夹爪 joint 控制。

Pico 输入链路 已有基础

现有 Franka motion controller 示例已实现右手柄 pose + trigger。

G1 自定义 USD 需要适配

需要确认 articulation、joint names、body names、gripper open/close 位置。

Headless 验证 可做

可以用 scripted/fake controller 模拟 trigger，自动跑开闭测试并保存报告和视频。

现有链路

现有 Isaac-Stack-Cube-Franka-IK-Abs-v0 motion controllers 的逻辑可以抽象为：

Pico 4 Ultra motion controller 通过 CloudXR / OpenXR 提供 controller pose 和 trigger。
OpenXRDevice 读取 CONTROLLER_RIGHT 的 pose 和 inputs。
Se3AbsMotionControllerRetargeter 把右手柄 pose 转为末端执行器绝对位姿命令。
GripperTriggerOrPinchRetargeter 把 trigger 转成 1 维 gripper open/close 命令。
Isaac Lab action manager 把 action 写入机器人 arm IK 和 gripper joint target。

对 G1 来说，Pico 输入层可以保留，核心变化是 action 末端的机器人映射。

目标变化

项目 Franka 示例 自定义 G1 目标
输入设备 Pico motion controller，右手柄 pose + trigger 继续复用同一输入语义
手臂控制 Franka differential IK G1 upper-body IK 或固定姿态下只测 gripper
夹爪控制 1DOF gripper binary open/close 自定义 G1 USD 上的 1DOF 并联夹爪 joint
原 G1 灵巧手 不涉及 原本 TriHand/Inspire 多关节逻辑需要替换或旁路

建议实现方式

1. 先建立自定义 G1 asset cfg

在 isaaclab_assets.robots.unitree 或项目自定义 asset 配置中新增一个 G1 cfg，指向本地 USD。 它应至少包含：

  • usd_path 指向 g1_29dof_dex1_1_v4_test_good.usd。
  • 合适的 prim_path，例如 /World/envs/env_.*/Robot。
  • 上肢、腰部、腿部、夹爪的 actuator 配置。
  • 是否固定 root link。早期建议固定 root，降低验证复杂度。

2. 枚举 USD 里的 articulation 和 gripper joint

需要确认 1DOF gripper 是同一个 articulation 下的普通 joint，还是 mimic/follower joint，或者独立 articulation。 这一步决定后续 action 怎么写。 

需要确认的信息：
- default prim / articulation root
- all joint names
- all body names
- gripper joint name
- gripper open position
- gripper close position
- gripper joint limit
- gripper drive stiffness / damping

3. 优先采用“IK 控手臂 + BinaryJointPositionAction 控夹爪”

不建议把 1DOF gripper 强塞进原 TriHand/Inspire 多关节 retargeter。 更清晰的结构是把手臂 IK 和 gripper 分开：

  • upper_body_ik: 控制 G1 左/右 wrist 或只控制右手 wrist。
  • gripper_action: 使用 BinaryJointPositionActionCfg 或等价 action 控制 1DOF gripper joint。

这样和 Franka 任务的结构最接近，debug 时也能独立验证 gripper。

4. Retargeter 层保留 Pico trigger 语义

可以复用 GripperTriggerOrPinchRetargeter 的语义：trigger 大于阈值则 close，否则 open。 如果 G1 action vector 的排列与 Franka 不同，可以新增一个更窄的 retargeter： 

G1OneDofGripperRetargeter:
  input:  CONTROLLER_RIGHT trigger
  output: [gripper_command]
  command convention:
    +1.0 = open
    -1.0 = close

Headless 开发与验证闭环

Headless 模式下不适合依赖真实键盘鼠标焦点做自动化测试。更可靠的方式是模拟 Pico motion controller 输入， 生成与 OpenXRDevice 相同的数据结构。

推荐闭环

  1. Load 目标 G1 USD，确认 articulation 和 gripper joint 可解析。
  2. 固定 base 或只启用 gripper，先跑 open-close-open smoke test。
  3. 脚本模拟 CONTROLLER_RIGHT trigger: 0.0 -> 1.0 -> 0.0。
  4. 每步读取 gripper joint position，判断是否达到 open/close 阈值。
  5. 用 headless camera 保存 MP4 或 PNG 序列。
  6. 输出 json / md 报告，记录成功与失败原因。

建议的自动化产物

产物 用途
out/g1_1dof_gripper_smoke.json 记录关节名、open/close target、实际位置、误差、成功状态。
out/g1_1dof_gripper_smoke.md 给人工快速阅读的测试报告。
out/g1_1dof_gripper_smoke.mp4 验证 gripper 开闭动作是否可视化正确。

实施顺序

  1. Asset probe: 编写或复用脚本枚举目标 USD 的 articulation、joint、body，确认 1DOF gripper joint 名称。
  2. Standalone gripper smoke test: 不进完整 Isaac Lab task，先用 Isaac Sim headless 直接控制 gripper joint open/close。
  3. Isaac Lab asset cfg: 新增自定义 G1 USD 的 ArticulationCfg，配置 gripper actuator。
  4. Task cfg: 基于现有 G1 fixed-base upper-body IK 或 locomanipulation task，新建一个 1DOF gripper 版本。
  5. Teleop device cfg: 增加 motion_controllers 设备键，复用右手柄 pose 和 trigger。
  6. Scripted headless test: 新增 fake motion controller 输入，自动跑任务并生成 report + video。
  7. Pico real-device test: 使用真实 Pico motion controller 跑 record_demos.py --headless。

主要风险

风险 影响 规避方式
gripper joint 不在主 articulation 内 Isaac Lab 单个 robot action 可能找不到该 joint 先用 USD/Articulation probe 确认结构；必要时单独建 asset/action。
gripper 是 mimic/follower 结构 只控制一个 joint 可能不会带动所有爪指 确认 mimic 关系；必要时控制多个 joint 或在 USD 中补驱动约束。
G1 IK 的 URDF 与自定义 USD 不匹配 手臂 IK 可能失败或 frame 名称不一致 先固定手臂只测 gripper；随后为自定义 USD 生成/校正 URDF 和 frame 名称。
全身动态导致验证不稳定 机器人姿态变化会影响 gripper 测试 早期固定 base，只测上肢和夹爪。
真实 Pico 输入不利于自动化回归 AI 无法稳定复现人工操作 增加 fake/scripted motion controller 作为 headless CI 输入源。

推荐最小里程碑

第一阶段只做 1DOF gripper headless smoke test： 不接完整遥操作，不做堆叠任务，只验证目标 USD 中 gripper joint 可以被 Isaac Sim headless 控制，并且能生成报告和视频。

通过后再进入第二阶段：把它接入 Isaac Lab 的 motion_controllers 设备和 G1 task。
