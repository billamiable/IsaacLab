实际 Enable 过程

1. 先确认 Docker/headless 能工作

目的不是立刻接 teleop，而是确认 AI 可以在容器里启动 Isaac Lab，并在无 GUI 的情况下执行脚本、保存本地文件。 

docker exec -w /workspace/isaaclab isaac-lab-232 \
  ./isaaclab.sh -p scripts/tools/<script>.py \
  --headless --device cuda:0

后续涉及 Pink/Pinocchio 的脚本统一加 --enable_pinocchio，涉及相机渲染的脚本加 --enable_cameras。

2. Headless 加载 USD 并解决相机视角问题

最早的截图只能看到机器人局部，说明“加载成功”和“可视化验收”是两件事。后续视频脚本都加入了全局相机逻辑：根据 robot body 和 scene object 的 world position 计算 bounds，再把 camera 放到能看到全局的位置。 

def compute_scene_bounds(env, robot):
    positions = [robot.data.body_pos_w[0]]
    for rigid_object in env.unwrapped.scene.rigid_objects.values():
        positions.append(rigid_object.data.root_pos_w)
    body_pos = torch.cat(positions, dim=0)
    center = (body_pos.min(dim=0).values + body_pos.max(dim=0).values) * 0.5
    return center, radius

可复用经验：任何 headless 验证视频都不要依赖默认 viewer 视角，应该在脚本里显式设置 global camera 和 close-up camera。

3. 确认 Dex1 gripper 的 joint 映射

通过 USD/Isaac Lab articulation probe 确认：整机是 33 joints，即 G1 29DoF body 加 4 个 Dex1 prismatic joints。右侧 gripper 实验先只控制两个右手 prismatic joints： 

RIGHT_DEX1_GRIPPER_JOINTS = [
    "right_dex1_finger_joint_1",
    "right_dex1_finger_joint_2",
]
RIGHT_DEX1_OPEN = 0.02449999935925007
RIGHT_DEX1_CLOSE = -0.019999999552965164

这里“1DOF gripper”是控制语义上的 1 维：Pico trigger 或 gripper scalar 只有一个值；物理实现上会同时写两个 prismatic joint target。

4. 做最小 gripper-only Isaac Lab env

新增 g1_dex1_gripper_only_env_cfg.py。它只保留 robot、ground、light、一个 BinaryJointPositionActionCfg，不接 IK，不放桌子和 cube。 

gripper_action = mdp.BinaryJointPositionActionCfg(
    asset_name="robot",
    joint_names=RIGHT_DEX1_GRIPPER_JOINTS,
    open_command_expr={... RIGHT_DEX1_OPEN ...},
    close_command_expr={... RIGHT_DEX1_CLOSE ...},
)

这个切片验证了：Isaac Lab action manager 能找到自定义 USD 里的右手 gripper joints，并且 binary action 能稳定驱动 open/close。

5. 加入固定下半身场景：table + cube

新增 g1_dex1_fixed_base_scene_env_cfg.py。它仍然只测 gripper action，但加入 table 和 cube，让视觉上更接近真实 teleop 环境。 

table: kinematic cuboid
cube:  rigid cuboid, pos=(0.38, 0.30, 0.78)
robot.spawn.articulation_props.fix_root_link = True

这一步证明：在 manager-based task scene 里，自定义 G1 Dex1 USD、桌子、物体、观测项、相机渲染可以共存。

6. 接入 Pink IK，控制上半身 wrist pose

新增 g1_dex1_fixed_base_ik_scene_env_cfg.py。它把 action 拆成两段： 

upper_body_ik:  14D = left_wrist_pose(7) + right_wrist_pose(7)
gripper_action: 1D  = right Dex1 open/close

这里选择固定 root/lower body，暂不做 locomotion；参考的是已有 fixed-base G1 / locomanipulation G1 示例。IK 用 URDF，仿真显示和物理用最终 USD。

实际遇到的问题是：现有 Pink action 默认手部关节并入 Pink action，例如原 G1 示例是 num_hand_joints=14。本轮实验采用 num_hand_joints=0，让 gripper 走单独 action term，因此临时改了部分 Pink 核心代码以跑通 reduced model 和 zero hand joints。

7. 增加 G1 Dex1 motion-controller retargeter

新增 g1_dex1_upper_body_motion_ctrl_retargeter.py，把 mock/真实右手柄位姿映射为 G1 wrist target。 

G1Dex1UpperBodyMotionControllerRetargeter:
  input:
    CONTROLLER_RIGHT pose
  output:
    [left_wrist_pose(7), right_wrist_pose(7)]
  current behavior:
    left wrist holds default pose
    right wrist = default pose + controller relative translation
    orientation held fixed for first safe version

gripper trigger 沿用现有 GripperTriggerOrPinchRetargeter。最终 mock Pico pipeline 是：

mock CONTROLLER_RIGHT pose + trigger
G1Dex1UpperBodyMotionControllerRetargeter 输出 14D wrist pose
GripperTriggerOrPinchRetargeter 输出 1D gripper command
拼成 15D action，交给 Isaac Lab env.step()

8. Headless 生成验证视频和报告

先做简单 open/close，再做 retargeter pipeline，再做更复杂的抓取式轨迹。最后一个轨迹不是只做前后运动，而是多段移动： 

home_open
  -> lateral_align_open
  -> forward_approach_open
  -> descend_to_grasp_open
  -> close_gripper
  -> lift_closed
  -> retreat_reopen

复杂轨迹参数为 x=0.18, y=0.24, z=-0.20，用于增加 IK 难度并模拟实际抓取动作形态。

可复用适配方法

  1. 先切资产，不切任务。 用最小脚本 load USD，枚举 articulation、joint、body、limits、drive。先证明名字和自由度。
  2. 把复杂任务拆成 action 切片。 先只测 gripper，再测 scene，再测 IK，再测 teleop input。每一步都能输出 JSON 和视频。
  3. 控制语义和物理 joint 分开。 “1DOF gripper”可以是一个输入标量，但底层可能写两个或多个 prismatic joints。
  4. IK 用 URDF，仿真用 USD，但必须建立 name/frame 映射。 如果 USD 是拼接资产，URDF 只承担运动学求解角色，不应该假设它等同于最终仿真资产。
  5. headless 视频必须自带相机策略。 自动计算 scene bounds，保存 global view + close-up view，避免“跑通但看不到”的问题。
  6. mock device 是 teleop 适配的核心工具。 真实 Pico 适合最终人工验收；开发和回归应使用 mock raw data 复现 pose/trigger。
  7. 尽量把适配逻辑放到新增文件。 核心 Isaac Lab patch 可以用于快速验证，但后续应收敛到 robot-specific cfg、retargeter、script，降低维护风险。

下一步建议

当前 pipeline 已经证明：自定义 G1 Dex1 USD 可以在 Isaac Lab headless 中被 mock Pico motion controller 控制，右手腕 IK 和右侧 1D gripper action 可以一起工作。

下一个更接近任务成功的验证应加入 contact/lift 指标：闭合后 cube 是否被夹住、cube 高度是否上升、cube 与 gripper 的相对距离是否保持。这样才能从“抓取动作形态验证”进入“物理抓取成功验证”。

工程清理建议放到后续单独做：恢复无关 Fourier yml；把 task 注册和 Pink 兼容改动从 Isaac Lab 核心里隔离出来；保留新增 G1 Dex1 cfg、retargeter、probe/render scripts 作为正式适配资产。
