SimReady 资产抓取验证方法

基于 Isaac Lab 3.0-beta2、Unitree G1 + Dex1_1 并联夹爪、mock Pico motion controller 的物理抓取验证记录。本文重点说明实验设计、抓取逻辑、failure case、局限性，以及如何在 Isaac Lab 3.0 / 2.3.2 环境中复现。

1. 验证目标

这个验证不是在做通用抓取算法，也不是证明机器人可以自动规划任意物体抓取。 它的目标更窄：给定一个 SimReady 资产，在已知机器人、已知夹爪、已知简单轨迹下， 判断这个资产的几何、碰撞、质量、摩擦等物理属性是否足够合理，能否支持基础接触抓取。

验证覆盖

  • USD 资产可以被 Isaac Lab 任务加载。
  • mesh / collider 尺寸和视觉外形大体一致。
  • 物体质量设定与实验目标一致。
  • Dex1 夹爪能通过物理接触夹住并抬起物体。
  • 失败时能区分尺寸、质量、摩擦、碰撞、可达性等原因。

不覆盖

  • 不做自动 grasp pose 搜索。
  • 不做复杂避障或动作规划。
  • 不证明真机一定可抓。
  • 不证明任意朝向、任意位置都可抓。
  • 不评估视觉策略训练效果。

2. 抓取逻辑

本实验使用 physical grasp：脚本只控制 G1 右手腕目标位置和 Dex1 夹爪开闭， 不使用 attach、吸附、直接写物体 pose 等辅助逻辑。物体必须靠夹爪和物体之间的接触力被抬起。
  1. 加载 G1 + Dex1 任务环境，选择目标物体 prim，例如 cube_2。
  2. 用 --object-usd 把默认 block 替换成待测 SimReady/YCB USD。
  3. 用 roll / pitch / yaw 设置物体放置姿态。
  4. 用 mock Pico 右手 motion controller 的位姿，生成右腕目标位姿。
  5. 用 mock trigger 标量从 0 到 1 控制 Dex1 右夹爪闭合。
  6. 按固定阶段执行：home open -> approach open -> close claws -> lift closed -> hold closed。
  7. 如果物体抬升超过阈值，并连续保持若干帧，则认为 physical grasp 通过。

当前脚本是 scripts/tools/render_mock_pico_g1_dex1_stack_cube_video.py。 关键参数包括： --object-usd、--object-mass、 --object-roll-deg、--object-pitch-deg、--object-yaw-deg、 --grasp-depth-x-offset、--grasp-center-z-offset。

3. 推荐实验设计

对盒状物体，不建议一开始做很大的组合矩阵。更实用的方法是： 让三个独立尺寸分别沿竖直 Z 方向放置，每个姿态下都让较短、可夹住的水平边朝向 gripper 闭合方向， 再对每个姿态测低 / 中 / 高三个抓取高度。

本文的 Zthin、Zmid、Zlong 表示物体哪条尺寸沿竖直方向： 例如 Zthin 表示薄的那条尺寸是高度，通常也就是大面平放在桌面上； Zlong 表示长边竖起来，物体更高、重心也更高。

层级 设计 目的
基础对照 先用同 bbox 尺寸的 block 抓取 确认轨迹、夹爪、IK、接触逻辑本身可用
物体姿态 3 个独立放置姿态：Zthin、Zmid、Zlong 覆盖物体低重心、中等高度、竖立高重心等情况
抓取方向 每个姿态下，把较短的水平边朝 gripper 闭合方向 验证资产可抓性，而不是故意用超出夹爪开口的方向制造失败
抓取高度 每个姿态测 low / mid / high 检查接触点变化对抓取稳定性的影响

对每个物体，最小但有解释力的矩阵是： 3 个放置姿态 x 3 个抓取高度 = 9 个 case。 这比 54 个 case 的完整网格更轻，也更适合早期资产验证。

4. 本次 sugar / cracker 示例结果

本次示例使用两个 YCB Axis-Aligned Physics 资产，并把质量改成更接近空纸盒的设置： sugar box 为 0.02 kg，cracker box 为 0.04 kg。 默认 YCB 质量更接近满盒物体，当前 Dex1 夹爪在这条简单轨迹下无法稳定抬起。

object mass pose low mid high 解释
sugar box 0.02 kg Zthin_clamp_mid pass pass pass 薄尺寸竖直，大面平放；夹持中等边，尺寸仍在 Dex1 可夹范围内
sugar box 0.02 kg Zmid_clamp_thin pass pass pass 当前常用姿态，夹薄边
sugar box 0.02 kg Zlong_clamp_thin pass pass pass 长尺寸竖直，物体竖立；夹薄边，仍能稳定抬起
cracker box 0.04 kg Zthin_clamp_mid fail fail fail 薄尺寸竖直，大面平放；需要夹住 cracker 的中等边，宽度约 16.4 cm，超过 Dex1 有效开口
cracker box 0.04 kg Zmid_clamp_thin pass pass pass 夹薄边，几何上可夹，物理抬升成功
cracker box 0.04 kg Zlong_clamp_thin pass pass pass 长尺寸竖直，物体竖立；仍夹薄边，能稳定抬起

详细结果和视频： out/isaaclab3/g1_dex1_ycb_short_edge_pose_height_sweep/summary.md， out/isaaclab3/g1_dex1_ycb_short_edge_pose_height_sweep/summary.json。

5. Failure case 怎么理解

cracker 的 Zthin_clamp_mid 失败不是坏事。 这个姿态下，夹爪需要夹住 cracker 的中等边，宽度超过 Dex1 当前有效开口。 因此低 / 中 / 高三个高度都失败，最大抬升接近 0。这是符合物理预期的失败， 也反过来证明当前实验不是 hidden attach 或吸附。

常见失败类型可以按下面方式分类：

失败类型 表现 可能原因 处理建议
尺寸失败 夹爪无法包住物体，物体几乎不动 夹持方向的物体宽度超过 gripper aperture 换姿态、夹薄边、改抓取方向，或换更大开口夹爪
质量失败 能夹住但抬不起来，或刚抬起就滑落 SimReady 默认质量偏向满盒 / 实物重量 按实验目标设定质量；空盒验证可覆盖为 0.02-0.04 kg
摩擦失败 夹住后沿接触面滑出 材料摩擦低、夹爪法向力不足、接触点不稳定 检查 physics material，或增大夹爪 effort / 改接触点
碰撞失败 视觉上接触，物理上穿透或离得很远 collider 与 visual mesh 不一致，convex hull 过粗或过小 检查 collider、bbox、contact offset、rest offset
姿态稳定性失败 抓之前物体倒下、滚动、弹飞 重心高、底面小、接触恢复不稳定 降低初始高度误差，增加 settle/warmup，或只标记为不稳定姿态
可达性失败 物体可抓，但手臂到不了或 IK 姿态异常 物体位置、桌面高度、腕部姿态不适合 G1 先用 block baseline 排除资产因素，再调物体位置和机器人姿态

6. 局限性

  • 没有抓取算法。 这里是 scripted grasp，不会自动搜索最优抓取点，也不会根据失败重试。
  • 物体规则性很重要。 盒子适合这种规则化姿态验证；杯子、瓶子、袋装物、带把手物体需要单独设计抓取点。
  • 质量会显著影响结论。 满盒 sugar/cracker 与空盒 sugar/cracker 是两个不同任务，不能混在一起解释。
  • 摩擦和夹爪力同样关键。 物体轻不代表一定可抓，低摩擦或接触面积过小仍会失败。
  • 尺寸必须先过几何可行性。 如果待夹方向比 Dex1 最大开口还宽，失败不能说明资产坏，只能说明夹爪不适合该姿态。
  • collider 可能和视觉 mesh 不一致。 SimReady 资产可能有简化 collider，必须把 bbox、collider approximation、contact offset 也纳入检查。
  • 仿真成功不等于真机成功。 真机存在延迟、柔顺性、控制误差、夹爪表面材料、物体真实变形等额外因素。
  • 当前只测一个机器人和一个夹爪。 换机器人、换 gripper、换腕部姿态后，结论需要重新验证。

7. 复现方法

7.1 启动 Isaac Lab 3.0-beta2 overlay 容器

cd /path/to/IsaacLab3
bash docker/teleop_dev.sh start
bash docker/teleop_dev.sh enter
cd /workspace/isaaclab

当前容器名通常是 isaac-lab-base-300b2。 本地输出挂载到 /workspace/host/out，建议所有 Lab3 结果写到 /workspace/host/out/isaaclab3/...，避免和 Isaac Lab 2.3.2 输出混淆。

7.2 单个 case 命令模板

./isaaclab.sh -p scripts/tools/render_mock_pico_g1_dex1_stack_cube_video.py \
  --headless --device cuda:0 --width 640 --height 360 \
  --frames 192 --warmup-steps 32 \
  --cube cube_2 --cube-x 0.50 --cube-y -0.16 --cube-z <object_center_z> \
  --object-usd <simready_or_ycb_usd> \
  --object-mass <mass_kg> \
  --object-roll-deg <roll> --object-pitch-deg <pitch> --object-yaw-deg <yaw> \
  --grasp-depth-x-offset <depth_offset> \
  --grasp-center-z-offset <low_mid_or_high_offset> \
  --grasp-z-offset 0.012 --retreat-x -0.02 \
  --out-mp4 /workspace/host/out/isaaclab3/<case>/video.mp4 \
  --out-json /workspace/host/out/isaaclab3/<case>/summary.json \
  --out-frames /workspace/host/out/isaaclab3/<case>/frames

7.3 资产检查

在跑抓取前，建议先用检查脚本读取 bbox、mass、collider、physics material。 这一步能提前发现“物体其实太宽”“质量不符合实验目标”“collider 不是预期形状”等问题。 

./isaaclab.sh -p scripts/tools/inspect_g1_dex1_object_physx.py \
  --headless --device cuda:0 \
  --cube cube_2 --cube-x 0.50 --cube-y -0.16 --cube-z <object_center_z> \
  --object-usd <simready_or_ycb_usd> \
  --object-scale 1.0 \
  --object-roll-deg <roll> --object-pitch-deg <pitch> --object-yaw-deg <yaw> \
  --out-json /workspace/host/out/isaaclab3/<case>/physx.json
如果 --object-usd 指向远程 Omniverse/S3 URL，需要容器有网络访问和资产缓存能力。 客户环境无法联网时，应把 USD 和依赖资源提前放到本地路径，并把命令中的 URL 改成本地路径。

8. Isaac Lab 3.0 与 2.3.2 注意点

主题 Isaac Lab 3.0-beta2 Isaac Lab 2.3.2 迁移注意
容器 当前使用 IsaacLab3/docker/teleop_dev.sh 启动官方 Lab3 + local overlay 2.3.2 通常使用旧 teleop docker；路径、镜像、挂载点不同
输出路径 统一写到 out/isaaclab3/... 2.3.2 结果建议写到独立目录，避免覆盖 Lab3 视频和 JSON
脚本 API 当前脚本基于 Lab3 的 AppLauncher、任务注册、action manager 2.3.2 中类名、import 路径、参数名可能不同，需要按旧 repo 对应脚本移植
四元数 Lab3 适配中已经特别处理姿态顺序和目标姿态 迁回 2.3.2 时要重新检查 xyzw / wxyz 约定，避免机器人倒置或腕部姿态错误
Teleop Lab3 已集成 isaaclab_teleop / isaacteleop 2.3.2 可能依赖项目内 patch 和旧 CloudXR runtime；mock 脚本可减少真实 Pico 依赖
资产路径 Lab3 当前可直接引用远程 YCB USD 或本地 runtime assets 客户 2.3.2 环境要确认 USD、mesh、material、依赖层都能被容器读到
物理参数 本实验显式支持 --object-mass override 2.3.2 若没有同样参数，需要在 scene cfg 或 spawn cfg 中补 mass override

迁移时建议先复现最小闭环：同尺寸 block 物理抓取通过 -> 一个真实资产单姿态中位抓取通过 -> 三姿态三高度 sweep。不要直接从完整矩阵开始，否则很难判断失败来自资产、脚本、容器还是版本差异。

9. 后续可以自动化的内容

  • 把三姿态三高度 sweep 固化成脚本，而不是手写 Python 批量命令。
  • 自动读取 bbox，判断每个姿态下 gripper 是否几何可夹。
  • 自动生成 HTML report，嵌入关键帧和视频链接。
  • 把 failure 分类写入 JSON：geometry / mass / friction / collider / reachability。
  • 加入同尺寸 block baseline 的自动对照。
  • 把资产本地化，避免客户环境受远程 USD 下载影响。
