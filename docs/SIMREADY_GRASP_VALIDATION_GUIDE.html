SimReady 资产抓取验证方法

基于 Isaac Lab 2.3.2、Unitree G1 + Dex1_1 并联夹爪、mock Pico motion controller 的物理抓取验证记录。本文参考 Isaac Lab 3.0-beta2 版本的方法，但重点记录 2.3.2 的复现方式和坑点： 四元数顺序、Euler 约定、物体 settle/warmup、输出目录隔离，以及 2.3.2 teleop retargeter 对结果的影响。

1. 验证目标

这个验证不是通用抓取算法，也不是证明任意物体都能自动抓取。它的目标是：给定一个 SimReady 或 YCB USD 资产， 在固定机器人、固定夹爪、固定 scripted mock Pico 输入下，检查物体的几何、碰撞、质量、摩擦和姿态稳定性是否能支持基础接触抓取。

验证覆盖

  • 资产能被 Isaac Lab 2.3.2 任务加载。
  • 物体 visual mesh / collider / bbox 与预期一致。
  • Dex1 夹爪通过物理接触夹住并抬起物体。
  • 失败能归因到几何尺寸、质量、摩擦、碰撞、稳定性或可达性。

不覆盖

  • 不做自动 grasp pose 搜索。
  • 不做复杂避障或动作规划。
  • 不证明真机一定成功。
  • 不评估视觉策略训练效果。

2. Isaac Lab 2.3.2 抓取逻辑

本实验使用 physical grasp：脚本只控制 G1 右手腕目标位置和 Dex1 夹爪开闭， 不使用 attach、吸附、直接写物体 pose 等辅助逻辑。物体必须靠夹爪和物体之间的接触力被抬起。

2.3.2 版本使用脚本：scripts/tools/render_g1_dex1_simready_grasp_validation_video.py。 它走旧版 teleop/motion-controller retargeter 路径，把 mock controller pose 和 trigger 映射到 G1 上肢 IK 与 Dex1 夹爪动作。

  1. 加载 Isaac-G1-Dex1-FixedBase-StackCube-Reachability-v0。
  2. 用 --object-usd 把默认 cube 替换成待测 USD。
  3. 用 --object-roll-deg / --object-pitch-deg / --object-yaw-deg 设置物体姿态。
  4. 用 mock Pico 右手 controller 的位姿生成右腕目标。
  5. 用 mock trigger 从 0 到 1 控制 Dex1 右夹爪闭合。
  6. 执行 home open -> pregrasp -> insert/open -> close -> lift -> hold。
  7. 如果物体抬升超过阈值并连续保持若干帧，则判定 physical grasp 通过。

3. 推荐实验设计

对盒状物体，建议沿用 Lab3 guide 的轻量矩阵：让三个独立尺寸分别沿竖直 Z 方向放置， 每个姿态下都让较短、可夹住的水平边朝向 gripper 闭合方向，再对每个姿态测 low / mid / high 三个抓取高度。

姿态含义抓取方向目的
Zthin_clamp_mid 薄尺寸沿竖直 Z，大面平放 夹较短的可夹水平边，通常是中等边 验证低重心平放状态
Zmid_clamp_thin 中等尺寸沿竖直 Z 夹薄边 验证中等高度状态
Zlong_clamp_thin 长尺寸沿竖直 Z，高重心竖立 夹薄边 验证高重心和 settle 稳定性

对每个物体，最小矩阵是 3 个放置姿态 x 3 个抓取高度 = 9 个 case。 当前 sugar + cracker 示例一共 18 个 case。

4. 2.3.2 特有坑点

四元数和 Euler 约定是最大坑。 Lab3 的 SimReady 脚本用 scipy.spatial.transform.Rotation.from_euler("XYZ") 生成 xyzw 四元数； Isaac Lab 2.3.2 的 init_state.rot 需要 wxyz。 直接复用数值会导致 Zmid_clamp_thin 这类组合旋转摆错，表现为“物体没有让短边朝向 gripper”。
问题表现正确处理
Lab3/Lab2 四元数顺序不同 同一组 RPY 在 2.3.2 里物体朝向不对 Lab3 RPY -> SciPy Rotation.from_euler("XYZ") -> xyzw -> 重排成 2.3.2 wxyz
不要用 2.3.2 的 math_utils.quat_from_euler_xyz 复刻 Lab3 脚本 (-90, 0, -90) 等组合旋转与 Lab3 SciPy 结果不等价 在脚本里显式使用 SciPy，保证和 Lab3 guide 的 pose 定义一致
高重心物体 warmup 不够 抓取开始前物体左右晃动；gripper 一靠近就把物体撞偏或只抬起一个角 对 Zlong_clamp_thin 这类高盒子增加 --warmup-steps，当前 cracker 使用 120
输出路径容易混淆 Lab3 和 Lab2 结果覆盖或写到容器内部临时路径 2.3.2 一律写到 /workspace/host/out/isaaclab232/...
2.3.2 retargeter 与 Lab3 direct-action 不完全一致 同样物体姿态下，gripper center、接触路径和闭合误差略有差别 优先保证物体 pose 正确，再用视频和 JSON 指标判断是否为控制路径差异

6. 单 case 命令模板

docker exec -w /workspace/isaaclab isaac-lab-232 ./isaaclab.sh \
  -p scripts/tools/render_g1_dex1_simready_grasp_validation_video.py \
  --headless --enable_cameras --device cuda:0 --enable_pinocchio \
  --cube cube_2 --cube-x 0.50 --cube-y -0.16 --cube-z <object_center_z> \
  --object-usd <simready_or_ycb_usd> \
  --object-mass <mass_kg> \
  --object-roll-deg <roll> --object-pitch-deg <pitch> --object-yaw-deg <yaw> \
  --grasp-depth-x-offset <depth_offset> \
  --approach-x-offset 0.0 \
  --grasp-center-z-offset <low_mid_or_high_offset> \
  --frames 144 --warmup-steps <16_or_120> \
  --global-width 960 --global-height 540 \
  --out-mp4 /workspace/host/out/isaaclab232/<case>/video.mp4 \
  --summary /workspace/host/out/isaaclab232/<case>/summary.json \
  --out-dir /workspace/host/out/isaaclab232/<case>/frames

对普通低重心姿态，--warmup-steps 16 通常够用；对 Zlong 这类高重心竖立姿态，建议先尝试 120 或更高。

7. Failure case 怎么看

不要把所有 failure 都当成坏资产。 cracker Zthin_clamp_mid 失败是合理的：该姿态要求夹住中等边，宽度超过 Dex1 有效开口。 这种 failure 说明实验没有 hidden attach 或吸附，反而是有效的几何约束检查。
失败类型表现可能原因建议
尺寸失败夹爪包不住物体夹持方向宽度超过 gripper aperture换姿态、夹薄边，或换更大夹爪
稳定性失败抓之前晃动、倒下、被轻碰后跑偏高重心、底面小、settle 不够增加 warmup，降低初始高度误差
质量失败夹住但抬不起或滑落质量偏重、夹爪力不足明确空盒/满盒任务，必要时 override mass
摩擦失败抬起时滑出material 摩擦低、接触面积小检查 physics material 或夹爪 effort
碰撞失败视觉接触但物理距离异常collider 与 visual mesh 不一致检查 collider、bbox、contact offset
可达性失败手臂姿态异常或到不了桌面/物体位置不合适先用 block baseline 排除资产因素

8. 复现顺序建议

  1. 先跑同尺寸 block baseline，确认轨迹、夹爪、IK 和接触逻辑可用。
  2. 再跑一个真实资产的单姿态 mid 抓取。
  3. 确认物体姿态后，再跑 Zthin / Zmid / Zlong 三姿态。
  4. 最后对每个姿态扩展 low / mid / high。
  5. 高重心姿态如果出现初始晃动，先加 warmup，不要急着调 grasp depth。

9. 后续可以自动化

  • 把 18 case sweep 固化成脚本，避免手写批量命令。
  • 自动读取 bbox，判断当前姿态的夹持宽度是否超过 gripper aperture。
  • 自动检测 warmup 后物体速度和姿态变化，决定是否继续 settle。
  • 自动生成 HTML report，嵌入关键帧、视频链接和 failure 分类。
  • 把远程 YCB/SimReady USD 本地化，避免客户环境受网络或缓存影响。
